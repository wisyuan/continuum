# Continuum：概念与技术可行性验证计划

初稿：2026-09-21；更新：2026-09-26。

状态：第一版设计基线已确认；以下实验均未执行。API、实现语言、数据库选型和具体性能指标待定。

本稿以[第一版设计基线](design-baseline.md)为设计依据，组织真实业务链与大规模合成依赖图两类验证。计划中的夹具和测量方式是实施建议，需要在具体实验开始前固定环境、数据和判据。

## 1. 本阶段要回答的问题

> 能否把 Cordis 的组合与生命周期机制映射到真实系统资源，管理局部失效、合法降级和恢复，并通过数据库承担大规模组件图的相关查询与计算？

本轮已经确定的方向：

- 持续服务关注影响遏制、部分有效性与局部恢复；动态更新是派生场景。
- 对象可以自由构造，生命周期控制作用于明确登记的受管单元与边界。
- 保留 Service、Fiber、能力绑定与副作用归属的区别，首个执行适配目标为 Cordis。
- 管理数据库承担全局时空依赖图的管理及相关计算，执行节点按需取得子图。
- 对可控且纳入恢复保证的外部操作，先记录意图，再执行并登记结果；恢复按契约核验。
- 实验覆盖执行进程退出与重启。整机意外断电恢复留到正式产品化，挂起感知与强制处置单独扩展。

设计共识不等于可行性证据。具体的恢复保证、接入成本和规模上限，需要以下实验给出结果。

## 2. 把概念落到可观察对象

本项目采用的工作定义：

> 持续服务是一种组合式运行时性质：在声明的故障模型、资源耦合与服务策略下，系统能够把局部扰动的影响限制在约定范围内，持续提供仍然合法的服务模式，并在条件稳定后完成可解释的局部恢复。

每个限定都需要落到可检查的对象：

| 对象 | 必须回答的问题 |
|---|---|
| 组件 | 哪个逻辑组件、哪次运行实例、当前属于哪次激活？ |
| 能力绑定 | 消费者实际使用哪个提供者？依赖是必需、可选还是可替代？ |
| 所有权 | 谁负责监听器、任务、连接、状态与外部操作的生命周期？ |
| 服务模式 | 哪些输出属于完整服务、合法降级或明确不可用？ |
| 影响范围 | 哪些依赖、共享资源和恢复关系会传播当前扰动？ |
| 恢复证据 | 什么证明资源已释放、旧任务已停止、业务条件已恢复？ |
| 覆盖范围 | 哪些行为受管理入口约束，哪些依赖接入方的契约和能力？ |

组件生命周期、对外服务模式和清理/恢复结果需要分别观察。例如，停止接收新请求可能已经完成，但后台任务仍在排空，外部操作的结果仍待确认。

最初的功能夹具可以采用有限、无环依赖和明确提供者，以简化结果核对。这属于样例选择；多提供者、依赖环、互斥资源及容量条件仍需分别建模，不能据此假定所有系统都存在唯一的“最大有效子图”。

恢复实验需说明外部条件何时稳定，以及操作如何完成、重试或保留未知状态。实验控制器的超时只用来结束观察，不代表 Continuum 已具备强制终止目标程序的能力。

## 3. 注册协议的验证内容

以下是协议需要覆盖的语义，不是已经确定的公开 API：

| 协议视角 | 验证内容 |
|---|---|
| 组件 | 身份与运行实例、能力提供、实际绑定、服务模式与管理边界 |
| 副作用 | 所有者、发生阶段、清理依赖、外部可见性、失败约束与完成证据 |
| 生命周期转换 | 触发条件、任务准入、在途工作、清理与恢复的完成条件及失败分支 |
| 图管理 | 相关版本读取、依赖与影响查询、约束检查、图变更确认与实际状态同步 |

注册方式采用结构化描述与可执行处理逻辑结合。黑盒行为的语义由维护人员显式提供；状态未知与身份无法关联需要保留，不能由相似日志自动推断为同一实例。

接口设计需要记录使用成本：必填声明、专用 API、业务代码改动和由运行时承担的管理义务。原语数量、模块划分及具体接口形态由实验需要决定。

## 4. 技术假设与证据缺口

| 编号 | 假设 | 当前依据 | 仍缺的证据 |
|---|---|---|---|
| H1 | 显式绑定与受管所有权支持局部启停和恢复 | Cordis 提供可复用的生命周期与组合机制 | 并发扰动、部分初始化与真实资源共享下的行为验证 |
| H2 | 声明和实际绑定可以界定扰动影响 | 已明确依赖、资源关系与托管边界 | 预测集合与独立观察结果的对照；隐式耦合的反例 |
| H3 | 受管入口可以形成可信的后续作用边界 | 访问撤销、任务准入与实例关联可作为接入条件 | 迟到异步回调、旧引用、清理失败和取消失效测试 |
| H4 | 外部操作的未知结果可以被显式管理 | 已确定意图记录、契约核验与本地持久化缓冲 | 外部已完成而本地缺少结果时的进程重启恢复实验 |
| H5 | 独立管理模型可以适配不同执行环境与存储后端 | 已确定 Cordis 首个适配目标和后端替换边界 | 首个实现的边界与成本；后续替代实现对共同语义的验证 |
| H6 | 数据库可以承担大规模依赖图的相关计算 | 已确定图管理职责与按需子图接口方向 | 查询正确性、增量维护、执行计划、内存和吞吐数据 |

文档核对的 Cordis 参考版本为 [f8ea3cd](https://github.com/cordiverse/cordis/commit/f8ea3cd50f1a5724e8e715995bcde131c9c12b2c)。已知机制与 Continuum 扩展的区别见[设计基线](design-baseline.md)。源码阅读不替代运行验证；实际实验需单独固定提交和依赖版本。

## 5. 两类验证对象

### 5.1 真实业务链

首个实验可以使用一个 Cordis 宿主连接真实数据库和消息系统。以下是建议的最小夹具，具体产品、业务数据与部署参数待确定：

| 组件 | 关系 | 外部可观察行为 |
|---|---|---|
| source | 提供数据库访问能力，拥有连接等资源 | 返回确定性数据并暴露可核验的连接状态 |
| processor | 依赖 source，拥有消息订阅与后台消费任务 | 处理带编号的消息；依赖失效时撤销相关受管活动 |
| enrichment | 为处理过程提供可选能力 | 缺失时 processor 进入预先声明的基础模式 |
| independent | 与上述组件无业务依赖 | 持续响应带请求编号的查询 |

业务数据写入是否纳入副作用管理，需要显式声明；连接、订阅和任务的生命周期管理不能自动推出业务写入可撤销。

外部操作实验另设可核验的接收端，用来记录操作是否完成。测试控制器在被测宿主之外运行，独立发请求、保存时间线并记录资源状态。组件共用事件循环、进程或其他资源时，需把相应耦合写进实验条件。

### 真实资源实验矩阵

以下实验均为计划，尚无通过或失败结果。E4 保留为后续扩展研究，其他条目用于首轮契约验证。

| 编号 | 操作与反例 | 必须观察的结果 | 将决定什么 |
|---|---|---|---|
| E1 依赖有效性 | 撤销并恢复 source；另撤销 enrichment；重复发送启停请求 | processor 停用或进入约定模式；independent 按声明继续服务；恢复后的绑定与模式正确 | 局部失活、降级和恢复能否正确映射 |
| E2 生命周期与清理 | 初始化中途抛错；重复启停；注入清理报错，并显式启用失败约束策略 | 成功清理的资源回到基线；未完成资源保留归属与记录；契约指定的冲突操作受阻，解除后可继续 | 所有权、清理次序和可选失败约束是否有效 |
| E3 并发与迟到作用 | 激活、撤销、恢复交错；旧异步任务迟到完成；消费者保留旧引用 | 受管入口按实例与契约处理操作；在途任务按声明结束或报告未知；旧结果不会错误归入新实例 | 实例关联、撤销与准入协议是否足够 |
| E4 故障域扩展 | 后续分别研究永久等待、事件循环阻塞和隔离执行环境 | 外部观察器记录实际影响，与声明的故障域对照 | 挂起感知、强制处置和隔离所需的独立能力 |
| E5 外部结果不确定 | 在意图已记录、外部操作已完成而结果未登记时终止执行进程并重启 | 意图可恢复；适配器核验实际结果；无法确认时保持未知；按接收端能力处理重试、去重或人工分支 | 进程级恢复、记录与核验协议的有效性 |
| E6 管理连接与背压 | 中断全局图管理连接；降低数据库消费速率，形成持续积压 | 本地可判定的撤销与清理按已确认规则执行；需要全局确认的变更等待；新记录准入受容量控制；已登记操作的结果和清理有预留空间 | 失联权限、本地持久化、同步恢复与容量策略是否成立 |

重复次数、超时与延迟阈值应在执行前按实验环境确定并记录，不能看到结果后调整通过标准。整机断电、操作系统崩溃和存储介质损坏不属于首轮进程恢复实验的保证范围。

### 5.2 大规模合成依赖图

合成图需要覆盖服务、运行实例、实际绑定、副作用归属及关系变化。规模、关系密度、依赖深度、热点分布和历史比例分别设置，以区分总图规模与单次操作实际影响范围。

下表是测量设计，不预设某个数据库已经具备目标能力：

| 编号 | 验证对象 | 观察与比较 |
|---|---|---|
| G1 查询正确性 | 相关子图、依赖闭包与影响范围 | 对可核对的数据使用独立参考结果，检查漏项、多项与版本混用 |
| G2 图变更与增量维护 | 新增、移除或替换关系，检查约束后提交 | 区分期望变更确认与实际执行结果；观察哪些数据和计算随局部变更更新 |
| G3 计算与内存位置 | 总图增长、局部查询、热点及大范围影响查询 | 同时测量执行节点、图管理服务和数据库；记录查询计划、传输量与内存，识别是否仍在某个管理进程完整加载全图 |
| G4 吞吐与积压 | 持续变更、突发写入、较慢存储与恢复追赶 | 测量写入吞吐、查询延迟、缓冲增长、反压触发及恢复后的积压消退 |

单次查询的结果本身可能覆盖大范围关系，应记录结果规模带来的成本。局部场景不应因实现习惯而默认加载整张全局图；是否达到该目标需要测量，而非仅由接口名称判断。

第一版只实现一个数据库后端。其他后端的替换能力可以后续验证，当前需记录哪些操作依赖该后端的具体能力。

### 5.3 独立观察判据

- 影响预测使用扰动前冻结的声明、实际绑定、资源关系和故障模型，不能事后根据失败日志倒推预测。
- 实际影响同时读取外部请求结果、组件实例身份与可枚举资源；运行时自身报告健康不构成充分证据。
- 功能夹具可以对比无故障、手工生命周期管理和候选协议实现，分别记录漏报与多报影响。
- 对小图枚举短事件序列，大图使用可复现的数据和扰动种子；失败时保留复现轨迹。
- 绕过受管入口建立反例，识别保证之外的共享状态与未登记行为。
- 只有意图而缺少结果时检查实际资源；记录同步完成不能替代外部操作完成证据。

## 6. 验证时需要保留的边界

### 6.1 停止与清理

关闭新调用入口、处理在途工作、回收本地资源和确认外部操作结果是不同事项。超时只说明未在期限内完成，不能证明任务已经停止。

清理仍在等待时复用 Cordis 的生命周期协调；清理回调已报错后是否继续阻止冲突操作，由资源注册契约明确启用。实验结果需要记录采用了哪种策略。

### 6.2 本地与跨节点

本地句柄撤销与远端旧操作失去执行权需要各自的协议。若承诺拒绝过期操作，实际执行入口或接收端需要具备可验证的条件。

跨节点操作权、并发版本确认和失联接管仍待设计。首个单宿主实验的结果只用于说明其声明范围内的行为。

### 6.3 外部资源恢复

登记意图、执行外部动作和登记结果分别观察。默认通过重新激活与资源核对恢复；进程内资源重建，外部遗留资源按契约接续、清理或重建。

实验阶段的记录确认只承诺所声明的进程级恢复能力。正式产品化再设计并验证整机意外断电后的关键记录耐久性，前提是存储介质仍可用。

### 6.4 黑盒行为解释

维护人员可以显式声明日志、事件或外部状态与行为阶段的对应关系，并提供清理与核验处理程序。实验报告需写明关联依据和覆盖范围。

无法关联或相互冲突的信号保留未知。自主推断与自动发现可以另行探索，首轮基线使用显式契约。

## 7. 后续交付顺序

1. **具体实验规格。** 依据设计基线，确定注册格式、状态转换示例、Cordis 版本、数据库后端和独立观察方法。
2. **真实业务链夹具。** 实现并运行 E1—E3、E5—E6，记录接入成本、受管边界和进程恢复证据。
3. **合成图夹具。** 实现并运行 G1—G4，记录查询正确性、计算位置、内存、吞吐和背压行为。
4. **可行性报告。** 按目标写明结论、前提、反例、尚未解决的问题及对应的原始记录。
5. **产品化设计。** 根据证据完善跨节点协议、生产服务集合和部署方式，开展整机断电恢复等后续验证；感知与隔离扩展按需另行安排。

步骤 2 和 3 可以独立推进。当前只完成设计与验证计划文档，实验代码和执行结果均未产生。

## 8. 执行前需要确定的参数

| 事项 | 需要记录的选择 |
|---|---|
| 真实业务链 | 数据库、消息系统、最小业务行为与可独立核验的资源 |
| 数据库后端 | 图查询、约束提交、版本读取和增量维护的具体实现 |
| 身份与记录 | 逻辑部件、运行实例、操作与资源的关联格式 |
| 缓冲策略 | 容量预算、结果与清理预留、进程级写入确认及同步方式 |
| 合成数据 | 总规模、关系密度、深度、热点、变化速率与历史比例 |
| 验收指标 | 查询与恢复延迟、吞吐、内存、积压阈值、重复次数及失败判据 |
| 实验环境 | 软件版本、硬件与存储条件、故障注入方式和复现步骤 |

未选定的参数保留为待定。每项结论都需要对应实际执行记录；未执行的实验继续标为未知。
